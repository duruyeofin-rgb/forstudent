# 04. 기술 구성과 데이터 구조

선생님이 개발자가 아니어도 시작할 수 있고, 무료로 시작해서 학급 단위로 운영할 수 있는 구성을 기준으로 합니다. 선생님이 다른 구성을 원하면 그쪽을 따르되, **개인정보 원칙(`03`)과 학생 입장 방식은 그대로 지킵니다.**

## 먼저 정합니다: DB가 필요한가?

| 상황 | 구성 |
|---|---|
| 학생이 연습만 하고 기록을 남길 필요가 없다 | 정적 웹사이트만 (DB·로그인 없음). 학생 정보는 아예 저장하지 않으므로 가장 안전합니다 |
| 교사가 학생별 기록을 보고 피드백해야 한다 | 아래 구성 (학급 코드 입장 + DB + 교사 화면) |

기록이 필요 없으면 DB를 만들지 않습니다.

## 권장 구성 (실제로 운영한 조합)

- 화면: React + Vite + TypeScript + Tailwind CSS
- 데이터·인증: Supabase (Postgres + 익명 로그인 + 행 단위 보안)
- 배포: Vercel
- 소리: 브라우저의 음성 합성(`speechSynthesis`, 한국어). 음성 인식은 브라우저 기능이라 기기마다 다르므로 판정을 단정하지 않습니다.
- 이유: 학생 기기에 설치가 필요 없고(태블릿 브라우저), 무료로 시작할 수 있고, 학급 단위 접근 통제를 DB가 직접 처리합니다.

폴더 구조 권장:

```
src/student/    학생 화면
src/teacher/    교사 화면 (로그인 필요)
src/lib/        서버 호출, 계산(성장 분석 등), 소리, 오프라인 저장
src/data/       교육 내용 (문항·낱말·단원) — 한 곳
scripts/        점검 스크립트 (내용 점검, 계산 점검, 개인정보 점검)
supabase/       SQL 파일 (실행 순서와 되돌리기 포함)
docs/           기획서, 검수 안내, 화면 캡처
```

## 학생 입장

- **학급 코드(숫자 6자리) + 번호**만으로 들어옵니다. 교사 화면에는 칠판에 띄울 QR과 코드가 있습니다.
- 서버는 입장 시 익명 로그인(Supabase *Anonymous sign-ins*를 대시보드에서 켜야 합니다)을 만들고, 서버 함수(`join_class(코드, 번호)`)가 학생 행을 만들거나 찾아 그 익명 사용자와 묶습니다.
- **공용 태블릿이면 항상 학급 코드부터** 시작합니다. 저장된 학생으로 자동 입장하면 이전 학생의 기록이 열리는 사고가 납니다. QR, 일반 주소, 새로고침, 브라우저 뒤로 가기 복원 모두 빈 코드 입력 화면에서 시작하게 합니다. (학생 한 명이 기기 한 대를 전용으로 쓰는 환경이면 선생님과 정해서 자동 입장을 허용할 수 있습니다.)
- 번호 선택 화면에는 입력한 학급 코드를 보여 줍니다.

## 교사 로그인

- 교사는 **아이디(별명) + 비밀번호**로 가입·로그인합니다. 이메일을 받지 않기 위해 내부적으로 `아이디@teacher.<앱이름>.invalid` 같은 가짜 이메일로 바꿔 인증 서비스에 넣습니다. 같은 아이디가 있으면 "이미 쓰는 아이디"라고 안내합니다.
- 단점: 이메일이 없어서 **비밀번호를 잊으면 복구할 수 없습니다.** 가입 화면과 README에 분명히 적습니다.
- 아무나 학급을 만들지 못하게 하려면 **초대 암호**(해시만 DB에 보관)를 통과한 계정만 교사로 등록합니다.

## 데이터 구조 (핵심 표)

`templates/schema-starter.sql`에 시작점이 있습니다. 이름은 프로젝트에 맞게 바꾸세요.

| 표 | 내용 |
|---|---|
| `classes` | 학급 이름, 코드, 인원 수, 교사 |
| `students` | 학급, **번호**, 익명 사용자 연결, 진행 상태(선택한 캐릭터·보상 등) |
| `progress` | 학생·단원·단계별 통과 여부, 첫 시도 맞힘 수 |
| `attempts` | **문항 하나하나의 결과**: 학생, 단원, 문항 번호, 고른 답, 정오, **첫 시도 여부**, 피드백, 시각 |
| `teacher_notes` | 교사 피드백 메모 (학생은 못 봄) |
| 활동별 표 | 미션·복습·이해 활동처럼 모양이 다른 활동은 **별도 표**로 둡니다 (정답률을 왜곡하지 않기 위해) |

설계 원칙:
- 성장 분석은 `attempts`에서 **계산만** 합니다. 계산 결과를 따로 저장하지 않으면 기준을 바꿔도 과거 기록을 다시 계산할 수 있습니다.
- 문항 번호는 교육 내용 파일의 순서에서 만들어지므로, 수업이 시작된 뒤에는 순서를 바꾸지 않습니다.
- 표가 아직 없어도 앱이 멈추지 않게 합니다. (새 기능의 표가 준비되기 전에는 그 기능만 건너뜁니다. "표 없음" 오류 코드를 알아보고 조용히 처리합니다.)
- 모든 SQL은 여러 번 실행해도 안전하게(`if not exists`, `drop policy if exists`) 쓰고, 파일 머리에 **적용 순서와 되돌리기 SQL**을 적습니다.

## 오프라인에서도 기록이 사라지지 않게

교실 와이파이는 끊깁니다. 저장은 **기기에 먼저 보관 → 서버로 전송** 순서로 합니다.

1. 기록(`attempt`, `progress`, 학생 상태 변경)을 기기 저장소의 대기열에 넣는다.
2. 대기열을 순서대로 보낸다. **네트워크 오류**(서버 오류 코드가 없는 실패)면 멈추고 남겨 둔다. **권한·형식 오류**(오류 코드가 있음)면 버리고 로그만 남긴다.
3. 입장할 때, 인터넷이 다시 연결될 때, 15초마다 다시 보낸다.
4. 같은 학생의 상태 변경은 하나로 합치고, 같은 키의 진도 기록은 마지막 값만 남긴다.
5. 서버에서 같은 ID의 재전송은 **한 번만 반영**(멱등)되게 한다.
6. 보내는 중인 전송을 기다린 뒤 다음 전송을 시작해서, 전송 중인 행을 덮어쓰지 않게 한다.
7. 기기 저장 공간과 서버가 모두 실패했다면 거짓으로 "저장됨"이라고 하지 않는다.

저장 직후에는 성공 화면을 따로 보이지 않고 **바로 다음 화면**으로 넘어갑니다 (저학년은 성공 화면에서 멈춥니다).

## 교사가 초기화했을 때 학생 기기가 따라가게

학생 기기에는 예전 값이 남아 있어서, 그냥 두면 다음 저장 때 교사가 초기화한 값을 덮어씁니다.

- 학생 기기가 **20초마다, 그리고 화면이 다시 보일 때** 자기 기록을 서버에서 읽어 기기 값과 비교합니다.
- 보낼 기록이 없고 마지막 변경이 몇 초 지난 안전한 때만 비교합니다.
- 달라졌으면 서버 값으로 맞추고 처음 화면(선택 화면)으로 돌아갑니다.
- 더 엄격하게는 초기화마다 **세대 값(epoch)**을 바꾸고, 서버가 오래된 세대의 재전송을 거부하게 합니다.

## 환경 변수와 배포

- 브라우저에는 **공개용 키**만 넣습니다: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. 서비스 역할 키는 어디에도 두지 않습니다.
- `.env.example`에 이름만 적어 두고(값 없이), 실제 값은 Git에 올리지 않습니다.
- 로컬에서 확인할 때 이 값이 없으면 화면에 연결 값 안내가 나옵니다. 확인용 서버를 띄우기 전에 값이 있는지 점검합니다.
- 배포 도구가 Git과 자동 연결되지 않으면 CLI로 배포합니다. 프로젝트 ID와 배포 주소는 프로젝트 지침 파일(`templates/project-instructions.md`)에 적어 두고, **배포 전에 대조**합니다.
- Supabase 무료 플랜은 7일 동안 사용이 없으면 일시정지됩니다. 방학 뒤에는 대시보드에서 복구하면 데이터가 남아 있습니다 (README에 적습니다).
