# 03. 개인정보와 안전: 들어가면 안 되는 정보

네 번째 질문의 답을 처리하는 문서입니다. **모든 프로젝트에서 항상 읽으세요.** 원칙은 하나입니다: *받지 않은 정보는 새어 나갈 수 없다.*

## 기본 금지 목록 (선생님이 말하지 않아도 제안하고 확인받기)

| 분류 | 넣지 않는 것 |
|---|---|

| 가정·보호자 | 보호자 이름·연락처, 가정 형편, 가정 이야기가 담긴 자유 글(주의 문구 필요) |

## 기록 저장 방식별 개인정보 기준

- **정적·간단한 Apps Script 앱**: 학생별 기록·학급 번호를 서버에 저장하지 않는 것을 기본값으로 합니다. 공용 기기에 이전 학생의 기록을 남기지 않습니다.
- **서버 기록형 앱**: 대시보드 유무와 관계없이 서버 측 인증·인가, 보관 기간, 삭제, 접근 분리를 실제로 검증합니다. **학급 코드+번호는 비밀 인증 수단이 아닙니다.** 번호를 아는 타인이 다른 학생 기록에 접근할 수 없다며 단정하지 않습니다.
- **Apps Script + Google Sheets 기록형**: 실행 사용자, 배포 접근 범위, 실제 이용자 식별, 서버 측 학생별 접근 통제, 시트 권한과 학교 정책을 별도 검토합니다. 안전한 본인 인증을 구현·검증하지 못하면 학생별 기록을 저장하지 않습니다. `references/09-simple-deployment.md` 참고.

## 서버 기록형 앱에서 학생을 구분하는 예시 (번호만)

- 학생 계정을 만들지 않고, **학급 코드(숫자 6자리) + 번호**로 입장합니다. 이름·이메일·비밀번호가 필요 없습니다.
- 서버에는 **번호만** 있습니다. 번호와 이름의 대응표는 선생님이 앱 밖(종이, 개인 파일)에 보관합니다.
- Supabase를 선택했다면 익명 로그인과 학생 행 연결을 사용할 수 있습니다. **익명 로그인이나 번호만으로 재입장 사칭이 해결되지는 않으므로**, 타인의 번호로 접근할 수 없는지 시험합니다.
- 내보내기 파일(CSV)에도 이름을 넣지 않습니다. 번호만 있습니다.

## 저장하는 것을 최소화하는 법

1. 기능마다 "이 정보가 정말 필요한가?"를 묻고, 필요한 최소 항목만 정합니다.
2. **음성**: 음성 인식 결과 **글자**만 교사 확인용으로 저장하고, 음성 원본은 저장·전송하지 않습니다.
3. **자유 글**(학생이 쓰는 글): 쓰기 전에 "이름, 전화번호, 사는 곳은 쓰지 않아요" 안내를 보이고, 교사만 읽게 하며, 교사가 부적절한 글을 지울 수 있게 합니다.
4. **카메라·마이크**: 학생이 직접 허락할 때만 켜고, 화면에 켜져 있음을 표시하고, 영상·음성을 저장하지 않습니다. 학교 정책과 보호자 동의는 선생님이 확인합니다.
5. **외부 AI 서비스**에는 학생이 입력한 내용이나 학생 식별 정보를 보내지 않습니다. 콘텐츠 제작(그림 생성 등)에만 쓰고, 끝나면 키를 폐기합니다.
6. 로그에 학생 정보가 찍히지 않게 합니다.

## 접근 통제 (RLS)

DB를 쓴다면 모든 표에 행 단위 보안(RLS)을 켜고, 기본은 "아무도 못 봄"에서 시작해 필요한 것만 엽니다.

- **학생**: 자기 행·자기 기록만 읽고 쓴다. 다른 학생·다른 학급은 못 본다.
- **교사**: 자기 학급의 학생·기록만 읽고, 지울 수 있다. 다른 교사의 학급은 못 본다.
- **로그인하지 않은 사람**: 아무것도 못 한다.
- 학생이 바꿀 수 있는 열을 제한합니다 (예: 학급 번호표나 인증 연결 열은 바꾸지 못하게 열 단위 권한).
- 입장·보상 지급 같은 민감한 동작은 서버 함수(RPC)에서 권한을 확인한 뒤 처리하고, 클라이언트가 임의의 값을 요청하지 못하게 합니다.
- **서비스 역할(관리자) 키는 앱 코드나 환경 변수에 절대 넣지 않습니다.** 화면(브라우저)에는 공개용 키만 사용합니다.

### 실제로 확인합니다 (만든 것을 믿지 않고 시험)

DB를 만든 뒤 아래 세 경우를 **실제 요청으로** 확인하고 결과를 보고합니다.

| 경우 | 기대 |
|---|---|
| 로그인하지 않은 요청 | 모든 표에서 0건, 쓰기 거부 |
| 학생 A가 자기 기록 | 읽기·쓰기 가능 |
| 학생 A가 학생 B(다른 학생/다른 학급)의 기록, 교사가 다른 교사 학급의 기록 | 읽기·쓰기·삭제 모두 거부 |

시험 데이터는 운영 학생이 아닌 **시험용 학급**에서 만들고, 끝나면 정리 여부를 선생님과 정합니다.

## 비밀값 관리

- 비밀번호·토큰·API 키는 채팅, Git, 로그에 출력하지 않습니다.
- `.env`, `.env.local`, 인증 파일, 배포 도구 설정 폴더는 Git에 올리지 않습니다 (`.gitignore` 확인).
- 비밀값은 서버 환경 변수에 두고, 공개용 키와 구분해서 이름 붙입니다.
- 커밋 전에 비밀값 패턴을 검사합니다 (`templates/privacy-check.mjs`).
- 비밀값이 한 번이라도 노출되면 즉시 폐기하고 새로 만든다고 선생님께 알립니다.

## 삭제와 초기화

- 교사 화면에서 **선택해서 초기화**할 수 있게 합니다 (풀이 기록·진도 / 별·보상 / 캐릭터·선택 / 학생이 쓴 글 / 교사 메모).
- 학급 전체 초기화는 **낱말을 직접 입력**해야 진행됩니다. 개별 학생 초기화는 표의 그 학생 줄에서 바로 할 수 있게 합니다.
- "지운 기록은 되돌릴 수 없어요"를 창에 분명히 적습니다. 백업 파일 내려받기를 둘지는 선생님이 정합니다 (파일에 학생 기록이 남기 때문에 보관 책임이 따릅니다).
- 학생이 앱을 켜 둔 기기가 예전 값으로 서버를 덮어쓰지 않게, 초기화 뒤에는 기기가 서버 값을 따라가게 합니다 (`04-architecture.md`).
- 학년 말 정리 절차(학급 삭제, 기록 삭제)를 README에 적어 둡니다.

## 학교·기관 정책

- 학교나 기관의 정보 보호 정책, 보안 기능을 끄거나 우회하지 않습니다. 막히면 멈추고 선생님께 보고합니다.
- 학교 정보 보호 담당자나 관리자에게 앱 사용 전에 확인받도록 권유합니다 (이용 약관, 보호자 안내, 개인정보 처리 방침).
- 앱 화면 아래에 저작권·제작자 표시와, 외부 자료를 쓴 경우 출처·라이선스를 표시합니다 (예: CC BY 자료는 저작자·링크·변경 표시).

## 코드로 지킵니다

선생님이 정한 금지 목록은 말로만 두지 말고 점검 스크립트로 지킵니다.

1. `templates/privacy-check.mjs`를 프로젝트의 `scripts/`에 복사합니다.
2. 금지 목록의 영어 열 이름·화면 입력 이름·한글 안내 낱말을 `forbidden.json`(양식: `templates/forbidden.example.json`)에 적습니다.
3. 커밋·배포 전에 `node scripts/privacy-check.mjs`를 실행합니다. SQL 열 이름, 화면 입력 칸, Git에 올라간 비밀 파일을 찾아 줍니다.
4. 이 스크립트는 **의심되는 곳을 알려 주는 도구**입니다. 통과했다고 해서 안전이 보증되지는 않으므로, 실제 접근 통제 시험과 함께 씁니다.
