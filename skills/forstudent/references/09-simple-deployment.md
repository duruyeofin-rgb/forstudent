# 09. 간단한 웹앱과 Google Apps Script 가이드

## 네 가지를 각각 선택

**기록 저장 / 교사 대시보드 / 개발 환경 / 배포 여부**는 별개의 선택입니다. 교육적 질문 네 가지를 먼저 확인하고 첫 기능을 하나로 좁힙니다. 기록과 대시보드는 기본값이 둘 다 '아니오'입니다.

## A. 기록 없는 간단한 학습 웹앱

- `index.html`에 HTML·CSS·JavaScript로 시작하고 정답 선택→힌트→재시도 기능 하나부터 만듭니다.
- DB, 로그인, GitHub 저장소, 교사 대시보드를 만들지 않습니다.
- 학생 이름·학급 번호·문항별 기록을 서버에 저장하지 않습니다. 공용 기기 로컬 저장소에도 학생 식별 기록을 남기지 않습니다.
- 브라우저에서 첫 화면·오답·정답·다시 시작·화면 크기·소리를 검수합니다.
- 공개 배포는 요청받았을 때만 별도 호스팅 방법을 안내합니다.

## B. Google Apps Script로 간단한 웹앱 배포 (GitHub 불필요)

학교 구글 계정은 관리자 정책에 따라 Apps Script나 외부 공개 배포가 제한될 수 있습니다.

1. [script.google.com](https://script.google.com)에서 새 프로젝트를 만듭니다.
2. `Code.gs`에 `doGet()`을 작성하고 `HtmlService.createHtmlOutputFromFile('Index')`로 화면을 반환합니다.
3. `Index.html` 파일을 만들고 HTML·CSS·JavaScript로 **서버 기록 없는** 학습 화면을 구현합니다.
4. 테스트 배포에서 실제 동작을 확인합니다. 그다음 필요하다면 '배포 > 새 배포 > 웹 앱'을 선택합니다.
5. **실행 사용자**와 **액세스 권한이 있는 사용자**를 확인하고, 학교 정책 및 선생님의 승인을 받은 후 공유합니다.
6. 학생 기기에서 접속·소리·문항·정답 동작을 다시 확인합니다.

```javascript
// Code.gs — 학습 기록 저장 기능이 없는 예시
function doGet() {
  return HtmlService.createHtmlOutputFromFile('Index');
}
```

`Index.html`에 화면을 구성합니다. React·Vite 프로젝트를 편집기에 그대로 붙여 넣는 방식은 아닙니다. 서버 비밀값을 HTML·클라이언트 코드로 전달하지 않습니다.

## C. 학생별 기록이 필요한 경우 (대시보드 유무 무관)

- 저장할 항목, 보관 기간, 삭제 방법, 학교 정책·안내 방식을 먼저 정합니다.
- **학급 코드와 번호만으로 학생 신원이 검증되는 것은 아닙니다.** 타 학생·타 학급의 기록을 볼 수 없도록 서버 측 인증·인가를 구현하고 시험합니다.
- Supabase·Vercel은 여러 선택지 중 한 조합입니다. 다른 DB·호스팅을 써도 권한 분리와 보안 점검은 필요합니다.
- **대시보드는 요청할 때만** 추가합니다. 요청하지 않으면 만들지 않습니다. 필요한 경우 안전한 교사 전용 조회·내보내기만 선택할 수 있습니다.
- **Apps Script + Sheets에 학생별 기록을 저장하려면** 실행 계정·실제 이용자 식별·서버 측 본인 확인·행별 접근 통제·시트 공유 권한을 별도 설계하고 실제 테스트해야 합니다. 공개 웹앱/시트에 학급 코드+번호만 입력하도록 해 운영하지 않습니다. 안전한 인증이 어렵다면 학생별 기록 저장을 제외합니다.
- 보호가 검증되기 전에는 실제 학생 정보를 입력하거나 공개 배포하지 않습니다.

## 연수에서 활용

- 노트북 없는 선생님은 네 질문에 답하고 첫 기능을 AI에게 설명하는 문장까지 작성합니다.
- 노트북이 있다면 간단한 HTML/JS 활동 하나부터 만들고, 배포는 선택형 심화 과제로 둡니다.
- Claude/Codex 스킬 자체에 GitHub 가입이 필수인 것은 아닙니다. 다만 Codex **클라우드 저장소 작업** 등 특정 환경은 GitHub 연결이 별도로 필요할 수 있습니다.
